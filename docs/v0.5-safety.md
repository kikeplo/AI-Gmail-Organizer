# v0.5 Safety Boundary

v0.5 introduces Gmail mutations, but the application separates **planning** from **execution**.

1. The user enters a command.
2. The agent finds the target messages.
3. The application builds a typed `PlannedAction`.
4. The UI displays a confirmation dialog describing the change.
5. Only an explicit confirmation allows execution.
6. Cancellation raises no Gmail mutation and leaves the inbox unchanged.

Supported mutations in v0.5:

- Archive messages (remove the `INBOX` label)
- Apply an existing Gmail label
- Create a Gmail label when the requested label does not exist

The application does not send or delete messages in v0.5.
